# Laboratory Work 2 — Assembly

## 1. Мета роботи

Дослідити, як C-код перетворюється на Assembly та машинний код.
Навчитися аналізувати арифметичні операції, умови, цикли,
виклики функцій та вплив оптимізації GCC.

## 2. Середовище

- Ubuntu
- GitHub Codespaces
- GCC
- GNU Binutils
- objdump
- Architecture: x86-64

## 3. Завдання 1 — arithmetic.c

Програма додає числа 5 та 7.

Результат:
Result: 12

Для отримання Assembly використано:
gcc -Wall -Wextra -O0 -S -masm=intel arithmetic.c -o arithmetic_intel.s

## 4. Завдання 2 — Assembly

Assembly є текстовим представленням машинних інструкцій.
Параметр -S зупиняє компіляцію після генерації Assembly.
Параметр -O0 вимикає оптимізацію.

Одному рядку C не обов'язково відповідає одна Assembly-інструкція.
Назви змінних C можуть бути відсутні в Assembly.

## 5. Завдання 3 — Арифметичні операції

| C | Типова Assembly-інструкція |
|---|---|
| a + b | add |
| a - b | sub |
| a * b | imul |

Для a = 10 та b = 20 результати:
- Додавання: 30
- Віднімання: -10
- Множення: 200

## 6. Завдання 4 — Умовний оператор

Умова if реалізується порівнянням і умовними переходами.
Інструкція cmp встановлює прапорці відповідно до порівняння.
Умовний перехід визначає, яка гілка виконуватиметься.

## 7. Завдання 5 — Цикл

Цикл for реалізується послідовністю інструкцій:
ініціалізація, порівняння, умовний перехід, тіло циклу,
збільшення лічильника та перехід до перевірки.

Для sum_to(5) результат дорівнює 15.

## 8. Завдання 6 — Виклик функції

Інструкція call передає керування функції та зберігає адресу повернення.
Інструкція ret використовує адресу повернення для відновлення виконання.
Цілочисельний результат функції на x86-64 Linux повертається в eax
для типу int.

## 9. Завдання 7 — Машинний код

Виконуваний файл містить машинний код та інші необхідні дані.
Команда objdump -d -M intel показує машинні байти та їх Assembly-представлення.

Таблицю з трьома інструкціями, адресами та байтами потрібно
заповнити за фактичним виводом objdump для власного executable.

## 10. Завдання 8 — Оптимізація

-O0 вимикає оптимізацію.
-O2 вмикає набір оптимізацій компілятора.

Оптимізація може скорочувати код, змінювати використання регістрів,
спрощувати обчислення та вбудовувати функції.

## 11. Завдання 9 — Constant folding

Вираз 10 + 20 може бути обчислений під час компіляції.
Компілятор може замінити його готовим значенням 30,
якщо це не змінює поведінку програми.

## 12. Завдання 10 — analyze.c

Фінальна програма містить:
- окрему функцію з двома параметрами;
- арифметичні операції;
- if/else;
- цикл;
- повернення результату.

Для analyze(5, 3) результат дорівнює 3.

## 13. Контрольні питання

1. ISA — набір інструкцій процесора та правила їх виконання.
2. CPU не виконує C-код безпосередньо: його потрібно транслювати у машинні інструкції.
3. Assembly — текстове представлення інструкцій, machine code — їх двійкове кодування.
4. Параметр -S генерує Assembly та зупиняє компіляцію до створення object code.
5. -O0 вимикає оптимізацію та полегшує аналіз початкової структури коду.
6. Operand — значення, регістр або адреса, з якими працює інструкція.
7. mov копіює дані між операндами.
8. cmp порівнює операнди, встановлюючи прапорці процесора.
9. if реалізується порівняннями та умовними переходами.
10. Цикл реалізується перевіркою умови, переходами та повторенням тіла циклу.
11. call викликає функцію та зберігає адресу повернення.
12. ret повертає керування за адресою повернення.
13. Один рядок C може перетворитися на кілька інструкцій або бути оптимізованим.
14. objdump -d дизасемблює машинний код виконуваного файлу.
15. -O0 та -O2 застосовують різні стратегії генерації коду.
16. Так. Компілятор може видалити код, який не впливає на спостережувану поведінку програми, відповідно до правил мови C.

## 14. Висновок

і повернення результатів. Також було досліджено вплив оптимізації
GCC на структуру згенерованого коду.
